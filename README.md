# 楓之谷：經典版 經驗值計算器

讀狀態列的經驗值，算出 EXP/hr 與升級剩餘時間，並把每一場存進 SQLite，
之後可以比較哪張地圖效率最好。

**不需要任何設定** —— 遊戲開著就直接跑：

```powershell
.\run.cmd track --label 樹林底層
```

程式會自己找到遊戲視窗、自己在畫面上認出 `149016[34.79%]` 那一串在哪、
用內建的字元模板開始算。不用框 ROI，不用標字元，不用校準。

完全不接觸遊戲程序：不注入、不 hook、不讀記憶體、不攔封包。

---

## 免安裝執行檔

`dist\MapleExpTool.exe` 是單一檔案，複製到任何一台 Windows 上雙擊就能跑 ——
不用裝 Python、不用裝任何套件。雙擊預設就是「開始追蹤」（開浮窗，沒有黑色的
cmd 視窗，工作列上有自己的按鈕）；要用其他子命令就從終端機帶參數，例如
`MapleExpTool.exe doctor`，輸出會印回那個終端機。因為它是視窗程式，PowerShell
不會等它結束就把提示字元印出來 —— 想等就 `MapleExpTool.exe report | more`
或 `Start-Process -Wait`。

### 自動更新

執行檔每次啟動會到 [GitHub Releases](https://github.com/andy971029/MapleExpTool/releases)
看有沒有新版（背景做，沒網路就當沒事）。有的話浮窗會跳一個提示：

- **立即更新**：先照一般流程問這一場要不要存，然後下載、換掉自己、重新開啟。
- **稍後**：這次不理，下次啟動再問。
- **略過這版**：這個版本不再提示，更新的版本照提。

換檔的方式是把正在執行的 `MapleExpTool.exe` 改名成 `.old`、新檔搬到原名
（Windows 不准覆寫執行中的 exe，但准改名），下次啟動再清掉 `.old`。下載的檔案
會跟 Release 上的 `.sha256` 比對，不符就丟掉。所以執行檔要放在**自己能寫入的
資料夾**（桌面、下載、D 槽都行；`Program Files` 不行）。

不想自動檢查：`MapleExpTool.exe track --no-update-check`、把設定檔 `config.json`
的 `check_updates` 改成 `false`、或設環境變數 `MAPLEEXP_NO_UPDATE=1`。
手動檢查／更新：`MapleExpTool.exe update`（加 `--check` 只看不裝）。

## 安裝

需要 Python 3.11+（開發環境是 3.14.7 64-bit）。

```powershell
cd D:\Project\maple-exp-tracker
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
```

兩個相依：`numpy`，以及 `windows-capture`（Windows Graphics Capture 的綁定）。
其餘都用標準庫 —— ctypes 直接綁 Win32、tkinter 做介面、PNG 編碼器自己寫。

| `run.cmd windows` | 列出可擷取的視窗 |

## 為什麼是截圖

評估過三條路，實際檢查這台機器上的遊戲安裝後結論很明確：

| 方向 | 結論 |
|---|---|
| **讀檔案** | 死路。遊戲是 Unity 6000.3.16f1 + IL2CPP，唯一的文字檔 `Player.log` 只有引擎噪音（`GfxDevice`、`Unloading N unused Assets`），**零遊戲狀態**。`StreamingAssets/aa/` 的 Addressables bundle 只有靜態資料。 |
| **抓封包** | 不值得。遊戲目錄有 `NGM64.exe`、`NGMDll64.dll`、`NGMResource.dll`，而 `Player.log` 裡的 `Ngsx.NgsxPlugin:Awake()` 證實反外掛模組在啟動時就載入。就算只做被動側錄不碰程序，這代 client 的加密也不是舊版那種能從明文 handshake 撈金鑰的做法。 |
| **定時截圖** | 可行，而且準。狀態列是固定 UI 字型、固定大小，模板比對準確率實質 100%，單次不到 1 毫秒。 |

## 幾個關鍵設計

### 擷取用 WGC，所以不管視窗模式還是全螢幕

Windows Graphics Capture 要的是視窗在 DWM 裡的**合成結果**，不是螢幕上看得到的像素。
所以遊戲全螢幕、被別的視窗蓋住、浮窗壓在上面，都照樣抓得到。OBS 的視窗擷取走的也是這條路。

實測這個遊戲：`PrintWindow` 直接失敗，從螢幕 BitBlt 則會在被遮住時抓到**別的視窗的像素**
（這比抓不到更危險）。只有 WGC 兩種情況都能正確拿到畫面。

沒裝 `windows-capture` 時會自動退回螢幕 BitBlt —— 功能仍可用，但會要求遊戲畫面沒被蓋住，
而且每次擷取前都會用 `WindowFromPoint` 驗證那塊區域確實屬於遊戲，不屬於就回報失敗。

### 內建字元模板，所以不用標字元

`src/mapleexp/builtin_templates.json` 的 24 張模板是從這個遊戲的狀態列實機採集的
（0-9、`[`、`]`、`%`、`.`，外加 5 組與數字黏在一起的小數點）。所以第一次執行不需要
一個字一個字標。校準精靈還在，但只有自動設定失敗時才需要。

### 自動定位，所以不用框 ROI

找法是**先找錨點字元，再往兩邊展開**：用 `%` 的模板在畫面下方做二維 IoU 比對
（整條狀態列只有經驗值欄位有百分比符號，HP/MP 雖然也是括號格式但裡面是斜線），
找到之後切一條窄橫帶讀成字串，再從 `%` 往右找 `]`、往左找 `[`、
往左吃掉括號前面那串數字。

對版面位置完全沒有假設，換解析度、換 UI 縮放都能自己找到。偵測結果會存進設定檔，
第二次執行就直接沿用。

ROI 存的是「距離畫面底部中央幾個像素」而不是相對比例 —— 楓之谷狀態列是
**固定像素大小、錨定在底部中央**的 UI，用比例存的話視窗一改大小就整個跑掉
（1920x1080 與 1366x768 都實測過）。

### 不需要等級經驗表

狀態列同時顯示絕對經驗值與百分比，兩者相除就能即時反推本級所需經驗：

```
need = 100 x 149016 / 34.79 = 428,330
```

所以**不內建任何硬寫的等級經驗表** —— 自己推導比抄一張可能記錯、改版還會失效的表
可靠得多，而且第一筆取樣就能算出來。

多次觀測用**區間交集**而不是取平均收斂：顯示的百分比只有兩位小數，每次觀測給出一個
`need` 的可能區間，真值必定落在所有區間的交集內，所以觀測越多區間越窄。

副作用是**等級完全是選用資訊**：升級時經驗歸零，只要知道上一筆取樣當下的 `need`，
就能把「上一級剩下的量」補回去，不需要知道等級數字。浮窗上等級顯示 `--` 是正常的。

### 時間軸用「活躍時間」

EXP/hr 的分母不是牆上時間，而是**活躍時間**。有兩種情況會讓時鐘停下來：

* **讀不到畫面**（切頻、讀取中）—— 中斷 ≤ 30 秒視為短暫遮蔽，經驗差值與時間都照算；
  超過就兩者一起捨棄（無法判斷那段時間是在打怪還是掛機，捨棄對兩邊都不偏）。
* **經驗值停滯超過 10 秒**（走路、補血、聊天、掛機）—— 超過門檻的部分不計入。
  門檻在浮窗的設定（齒輪）按鈕裡改，跟取樣頻率放在一起；設 0 就不判定閒置。
  等級很高、單隻怪間隔本來就超過 10 秒時
  要調大，否則速率會算得偏高。
* **還沒開始練**—— 程式一開就是閒置，拿到第一筆經驗之前的時間一秒都不算，
  先開程式再整理背包、走到練功點都不會稀釋速率。一點經驗都沒拿到的場次在
  關閉或重設時直接丟掉，不會問要不要儲存。

浮窗左上角的狀態就這三種：**追蹤中**（綠）、**閒置中**（橘）、**無法讀取**（紅，
連續幾格讀不到經驗值 —— 多半是切頻、讀取畫面，或狀態列被滑鼠／遊戲內視窗擋住）。

結束停滯的那一筆**整段算進去** —— 那隻怪確實是在那段時間內打死的，
不算的話分母會趨近零，速率會噴成天文數字。

一旦進入閒置，速率就「凍結」而不是繼續往下掉：你去補個血回來，看到的應該還是
剛剛打怪的效率。

### 中文用 Windows 內建 OCR，前處理用「線性解混合」

角色名、職業、地圖名用 **Windows 內建的 OCR 引擎**辨識（`winrt-Windows.Media.Ocr`，
這台機器上 `繁體中文 (台灣)` 現成可用）—— **不用下載模型、不用裝外部執行檔**。

前處理是成敗關鍵，而且關鍵不在放大倍率，在**怎麼把字從底色裡挑出來**。遊戲 UI 是
2D 點陣圖，一塊文字區只用三種顏色（底色、文字、陰影），但抗鋸齒把它們混成幾百種
中間色；白字跟黑陰影各半混出來的灰，亮度剛好跟底色差不多，用亮度門檻會在筆畫
中間挖洞，字越小挖得越多。既然調色盤固定，就逐像素解
`P = a·文字 + b·陰影 + c·底色`，最小平方解出來的 `a` 就是文字覆蓋率 —— 把抗鋸齒的
次像素資訊原封不動還原。底色從畫面上面積最大的顏色量出來，所以暗底狀態列、淺藍
小地圖、純白面板標題都是同一套程式。實測小地圖「迷霧森林／奇幻村」：亮度門檻
18 幀全讀成 `幻村`，解混合 18 幀全對，連 19 劃的「霧」都讀得出來。

其餘兩個仍然必要的步驟：**雙線性放大**（最近鄰會把筆畫變成方塊）、**四周留白**
（沒有邊距時引擎常常整張放棄）。職業與角色名要**分兩行各自辨識** —— 兩行靠太近，
整塊丟進去引擎會把它們併成 `獵人卍弘法艾德卍`。

角色名與職業**至少每 5 秒重新確認一次**（換角色、或第一次剛好被擋住讀錯都能修正）。
實際跑 OCR 的只有「那塊像素變了」的時候 —— 像素沒變，重跑必定得到一樣的答案。
職業是封閉集合，OCR 結果會再跟內建的職業清單做編輯距離比對（實測出現過 `槍騎兵`
讀成 `搶騎兵`，一個字的差距就修回來了）。客戶端的資料檔裡沒有一張乾淨的職業表
—— 名字只散在 NPC 腳本字串與技能書名裡 —— 而職業清單幾年才動一次，所以內建。

**OCR 不拿來讀數字。** 實測過把經驗值欄位 `298198[69.63%]` 用同樣的前處理丟給
OCR：兩種中文引擎 × 六個倍率 × 三種邊距 × 兩種裁切共 72 種組合，**沒有一種讀對**
—— 中文引擎把 `[` 讀成 `【`、小數點讀成 `一`、還會漏掉數字（典型輸出
`998【69-631`）。模板比對 30 幀全對、每幀 12 毫秒；OCR 每幀 72 毫秒而且全錯。
等級方塊 OCR 倒是 30 幀全對，但要 25 毫秒，模板只要 0.1 毫秒，所以等級是
「模板優先、沒學過的字形才退到 OCR」。

### 面板用「白色標題列」通用定位

每個功能視窗（小地圖、背包、技能欄、角色資料）都可以被玩家拖到任何位置，
所以不能寫死座標。但它們的外框樣式一致：最上面一定有一條**純白底、純黑字的
標題列**（實機量過四個面板，底色都是 `BGR(255,255,255)`、文字都是 `BGR(0,0,0)`）。

於是流程是：找出所有白色細長條 → 每條 OCR → 跟已知標題做**模糊比對**
（1 − 正規化編輯距離）→ 比對到的就是那個面板，標題列下方就是內容區。

模糊比對是必要的，OCR 會差一兩個字：`技能攔`→`技能欄`、`小地`→`小地圖`。
而背包裡的楓幣欄位也是白底黑字細長條（OCR 讀到 `128,231`），它配不上任何
標題所以自然被排除 —— 這比「只找畫面左上角」那種位置假設可靠得多
（玩家把小地圖拖走之後，位置假設就整個失效了）。

填充率門檻訂 0.40 也是量出來的：「小地圖」只有三個字，黑字就吃掉 49%
（實測 0.51），其他面板是 0.76–0.80。訂 0.55 就會漏掉小地圖。

搜尋一次要對每條標題列跑 OCR（約 0.9 秒），所以**找到就快取**；
狀態列正常、地圖名卻連續 5 格讀不出來才忘掉重找（一格就忘的話，換圖的讀取畫面會把
面板踢掉），讀取畫面期間不搜尋也不忘；20 秒的間隔只在搜尋失敗後才開始算。
玩家搬動視窗後會自動修復。

要支援新面板只要在 `KNOWN_TITLES` 加一個字串。

### 地圖：指紋負責「區分」，客戶端清單負責「取名」

我們要的是「**區分**地圖」而不是「**讀出**地圖名」。同一張地圖每次渲染的像素
完全一樣，所以對地圖名那塊取雜湊就 100% 可靠 —— 統計全部掛在這個指紋上，
名字只是給人看的，改名不會動到任何數字。

認定換圖需要指紋**連續穩定三次**。這一條擋掉了所有誤判：小地圖被收合、被移動、
或預設位置剛好對到遊戲場景時，那塊區域每一幀都在動，永遠穩定不下來，
於是地圖維持「未知」而不是亂跳。

名字則是 OCR 讀到幾個字算幾個，再拿去跟**客戶端自己的地圖清單**比對、挑編輯距離
最近的一張。清單每次啟動都直接從遊戲安裝目錄的 Addressables bundle
（`StreamingAssets/aa/w/json_*.bundle`）讀出來：`Map` 表是純 JSON 的 TextAsset，
不用解 type tree，自己走一遍 UnityFS 格式（只多依賴 `lz4`）就能拿到 1671 筆
「地區＋地圖名」。不附快照是因為清單會隨改版變，而玩家機器上的客戶端版本一定
跟他正在玩的一致；整個流程實測 43 毫秒，不值得快取。比對前做 NFKC 正規化，因為
客戶端自己的編號寫法就不一致（`森林迷宮I` 用 ASCII `I`、`猴子森林Ⅱ` 用 U+2161）。
比錯了在結束視窗或用 `run.cmd maps --name <ID> <名稱>` 改一次，之後都認得。

最常比錯的是**結尾的羅馬數字**：673 張地圖有 119 張以 Ⅰ／Ⅱ／Ⅲ 結尾，而 OCR 會把
`Ⅱ` 讀成 `LL`、`Ⅲ` 讀成 `川`（實測 `戰火之地沼澤地LL` 跟 Ⅰ、Ⅱ 同分，硬挑成 Ⅰ）。
清單裡沒有任何名字含 `L` 或 `川`，所以比對前直接把它們換成 `I`／`III`，
不會誤傷別的名字。

### 等級會自己學

等級用的是跟狀態列不同的粗體字型，每個數字包在自己的橘色方塊裡。方塊很好定位
（色鍵一抓就中，再用已定位的經驗值欄位限定「同一列、在它左邊」就唯一了），
但畫面上一次只看得到目前等級用到的那幾個數字，沒辦法一次採集完。

所以做成**邊玩邊學**：每次升級新等級必定是舊的 +1，新出現的字形就能自動標上
正確數字。玩一陣子十個數字就齊了。

但這招有個洞：學習只發生在升級的當下，玩家中途才開程式時，只要目前等級用到
沒學過的數字就整個讀不到（實測模板檔裡只有「4」，所以 44 讀得到、45 讀不到）。
所以模板認不出來時會**退到 OCR**。等級方塊只有 22x13，遠低於 OCR 引擎的設計
尺寸，單一倍率不可靠 —— 實測掃過 54 種（倍率 × 邊距）組合只有 18 種會回答，
但**回答的全部一致**。於是做法是多試幾個倍率、要全部同意才採用，讀出來之後
順手把字形教給模板，下次就走 0.2ms 的快路。`run.cmd level <等級>` 仍然可用，
但不再是必要步驟。

### 畫面只留統計，不留影像

每一格擷取到的畫面處理完就丟：經驗值欄位切成字元比對完即釋放、角色名與地圖名
那塊像素只留一個 6 位元組的指紋（判斷「有沒有變、要不要重跑 OCR」）。
落地的影像只有兩種：每張地圖第一次出現時存一張地圖名區的 PNG 縮圖進資料庫
（`maps.thumbnail`，約 1–2 KB，`maps` 指令會匯出來讓你對照取名），
以及 `--debug-frames` 開著時辨識失敗的 ROI（最多 40 張）。

### 存的是「段」，不是每秒的取樣

資料庫裡的基本單位是**段**：同一隻角色、在同一張地圖上連續練的一段。換圖或換角色
就切一段。報表要的數字 —— 練了多少、幾 %、多久、平均 /h、峰值 /h（段內 5 分鐘窗的
最大斜率）、死亡與升級次數 —— 全部在追蹤時線上算好，段結束時整筆寫入。

每秒的取樣**不存**。曾經存過：每小時 230 KB，一個月就幾十 MB，而且除了「事後重算
峰值」之外沒有任何功能讀它；峰值改成線上算之後就沒有存的理由了。舊資料庫第一次
開啟時會把那張表丟掉並回收空間（實測 3 MB → 68 KB）。

換角色是用狀態列的角色名偵測的：畫面消失又回來（選角色畫面）的那一格會立刻重新
確認是誰，名字變了就把舊段結束、追蹤器重設基準 —— 兩隻角色的經驗值之間沒有可比
較的關係，不重設的話會被記成一次死亡。

### 速率用線性回歸，不用首尾相減

首尾相減對單點雜訊與區間端點極度敏感。回歸把整個時間窗的資訊都用上。
預設同時顯示 5 分鐘 / 15 分鐘 / 1 小時三個窗，短期窗才看得出「現在這隻怪划不划算」。

### 意外轉換要下一筆確認才採信

單格辨識雜訊是實務上最常見的失效模式。任何「意外」的轉換 —— 經驗下降、升級、
單次暴增 —— 都會先被扣住，等下一筆取樣佐證才採信，代價是一次取樣的延遲。
這能把「某一格把 1234 讀成 91234」這種錯誤完全擋掉。

死亡與升級都是「經驗變少」，靠下降幅度區分：升級會從接近滿值掉到接近零，
死亡只掉本級所需經驗的一小部分。

### 辨識用模板比對，不用 OCR

要辨識的字形只有 `0-9` 加幾個符號，而且字型、大小、顏色都固定。
模板比對準確率實質 100%、單次不到 1 毫秒、不用背一個 OCR 引擎的相依。
通用 OCR 在這種小字號上反而容易把 `8` 讀成 `B`。

相似度用 IoU（交集/聯集）而不是「相同像素比例」—— 後者會因為背景像素佔多數
而讓所有分數都很高、彼此難以區分。分數不夠高、或前兩名差距太小時，
**寧可讓這一格失敗，也不記下錯的數字**。

字元切割回傳的是**每個字元自己的像素**，不是矩形裁切：`[27.50%]` 的小數點與後面的
數字其實是兩個互不相連的區塊，但外接矩形在欄位上重疊了一格，任何垂直切線都會
切掉其中一邊。依連通區塊取像素才分得乾淨。

## 已知限制

- 遊戲**最小化**時擷取不到（WGC 也不行，視窗沒有在合成）。
- 遊戲在**獨占全螢幕**時浮窗會看不到 —— GPU 直接掃描輸出遊戲的緩衝區，
  桌面合成整個被跳過，任何置頂視窗都畫不上去。這是 Windows 的限制。
  **擷取與統計完全不受影響**；想看浮窗就把遊戲切成視窗或無邊框視窗。
  程式啟動時會偵測並提示。
- 換解析度或視窗大小後，存下來的 ROI 可能偏幾個像素（狀態列不是嚴格錨定在
  底部正中央）。啟動時會先用存的 ROI 試讀，讀不到就自動重新定位，所以通常不用管；
  但如果偏得剛好把整個數字切掉，讀到的是「少一位數」的合法數字，這種情況目前
  抓不到，`doctor` 看到數值不對就跑一次 `calibrate`。
- 換解析度或視窗大小後，存下來的 ROI 可能偏幾個像素（狀態列不是嚴格錨定在
  底部正中央）。啟動時會先用存的 ROI 試讀，讀不到就自動重新定位，所以通常不用管；
  但如果偏得剛好把整個數字切掉，讀到的是「少一位數」的合法數字，這種情況目前
  抓不到，`doctor` 看到數值不對就跑一次 `calibrate`。
- 狀態列如果沒有顯示絕對經驗值（只有百分比），這個工具不適用 ——
  百分比只有兩位小數，高等級時解析度完全不夠。
- 只支援 Windows（整個擷取層是 Win32）。
- 等級的字形是邊玩邊學的；還沒學過的數字會先用 OCR 讀（多倍率互相印證），
  讀出來就順手學起來。OCR 若連三次都讀不出同一組字形就會放棄它，那時等級會
  顯示 `--`（可以用 `run.cmd level <等級>` 手動教）。計算本身不需要等級。
- 地圖偵測需要小地圖是**展開**的（看得到標題列）。收合後地圖會變成「未知」，
  經驗統計不受影響。位置可以隨意拖動。
- 面板標題的 OCR 偶爾會差一兩個字（`技能欄` 一直讀成 `技能攔`），目前靠模糊
  比對吸收。若未來要支援標題很相近的面板，這裡會需要更強的判準。

354 個測試，全部不需要遊戲在跑：核心邏輯（解析、經驗表推導、追蹤狀態機、統計）

### 網頁版原型（實驗）

`web/` 是把同一套辨識與追蹤程式碼搬進瀏覽器的實驗：用 Pyodide 跑 Python，畫面來源
是瀏覽器的「分享視窗」（`getDisplayMedia`），目前做到**讀經驗值、算 EXP/hr、讀等級／
職業／角色名**，沒有地圖、不存資料庫。

經驗值用桌面版同一套模板比對（已在真實遊戲畫面上驗證）。等級、職業、角色名的
文字辨識改用 Tesseract.js：瀏覽器沒有 Windows 內建的 OCR 引擎。中文（職業、角色名）
走 `chi_tra`，等級的數字走英文模型，因為實測同一塊 22x13 的等級方塊，英文模型在
3/4/6/8 倍都讀出 45，中文模型 4 個倍率只有 2 個有回答。語言檔第一次要下載（幾十 MB），
Tesseract.js 會存進瀏覽器的 IndexedDB。

```powershell
.\web\serve.cmd        # 打包 src/mapleexp 成 web/mapleexp.zip，然後在 localhost:8765 開一個靜態伺服器
```

用 Chrome 或 Edge 開 http://localhost:8765/ ，按「分享遊戲視窗」，在對話框選「視窗」
分頁、挑遊戲。第一次載入要抓約 10 MB 的 Pyodide 與 numpy，之後瀏覽器會快取。
頁面下方會放大顯示程式實際看到的經驗值欄位像素，讀不到時先看那裡。

跟桌面版的差別只有 `web/shim/` 裡一個替身模組（取代 ctypes 綁 Win32 的擷取層）
與 `web/bridge.py` 的膠水；`vision/`、`core/` 一行都沒改。

### 發布新版

版本號只有一個來源：`src/mapleexp/__init__.py` 的 `__version__`（`pyproject.toml`
從那裡讀）。改完、commit 之後：

```powershell
.\release.cmd --notes "修了什麼"     # 打包 + sha256 + push + 建 GitHub Release
.\release.cmd --dry-run             # 只打包與檢查，不發布
```

需要 [GitHub CLI](https://cli.github.com/)：`winget install GitHub.cli`，然後
`gh auth login` 登入一次。腳本會拒絕在工作目錄不乾淨、或這個版本已經發布過的
情況下執行。Release 上會有 `MapleExpTool.exe` 與 `MapleExpTool.exe.sha256`
兩個附件 —— 執行檔的自動更新（`src/mapleexp/update.py`）靠的就是這兩個檔名，
不要改。

```
src/mapleexp/
├── config.py                設定、ROI 錨點模型
├── update.py                自動更新：查 GitHub Releases、下載、驗證、換檔
├── autosetup.py             內建模板載入 + 自動設定
├── builtin_templates.json   實機採集的字元模板
├── gamedata.py              讀客戶端 UnityFS bundle，取出官方地圖清單
├── testfont.py              自我測試用的內建點陣字型
├── storage.py               SQLite
├── win32/                   ctypes 綁定、視窗查找、擷取（WGC / screen）
├── vision/                  二值化、切割、模板比對、面板偵測、OCR、身分辨識、PNG
├── core/                    解析、等級經驗表、追蹤狀態機、統計、場次管線、地圖／職業名稱比對
└── ui/                      校準精靈、置頂浮窗、結束視窗、更新提示
```

資料檔都在 `%LOCALAPPDATA%\MapleExpTracker\`（可用環境變數 `MAPLEEXP_HOME` 改）：
`config.json`、`tracker.db`、`exp_table.json`、`gamedata.json`（上次在哪找到客戶端的
地圖表）、`templates/level.json`（邊玩邊學的等級字形；`digits.json` 只有自行校準時才有）、
`map_thumbs/`、`debug/`。遊戲裝在找不到的地方時，用 `MAPLEEXP_GAME_DIR` 指過去。
